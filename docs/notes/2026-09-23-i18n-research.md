## 1. Есть ли интерфейсная локаль, где она хранится и кто её читает

Да. В dsh есть клиентская locale-служба `ctx.locale` с каталогом языков, словарями, активным locale и `locale/change`: `packages/client/locale/src/client/index.ts:81-95, 152-160, 162-175`. Это не просто значение из окружения.

Явный выбор хранится как `locale.preference` в namespace `locale` (тип/ключ — `packages/client/locale/src/locale-settings.ts:5-9, 23-32`). На стороне Host locale-плагин регистрирует эту схему через `ctx.settings`: `packages/client/locale/src/index.ts:12-21`. Файловый settings provider по умолчанию хранит пользовательские namespaces в `settings.yaml` в dsh home, допускает явный путь и YAML/JSON: `packages/settings/settings-file/src/index.ts:21-30, 50-68`; dsh docs подтверждают единый settings документ и горячую загрузку: `packages/settings/settings-file/README.md:12`.

Клиентский плагин может читать активный locale через cordis `ctx.locale` (сервис предоставляется в `packages/client/locale/src/client/index.ts:539-547`), а также через `ctx.inject(['locale', ...])`. Служба подключает Host-backed `settingsScope` и читает/подписывает его (`packages/client/locale/src/client/index.ts:182-192, 280-292, 530-547`). Host-плагин не получает `ctx.locale`, но при наличии settings provider может читать namespace через `ctx.settings`; сама locale-схема регистрируется именно этим сервисом (`packages/client/locale/src/index.ts:16-21`). Следовательно, ответ — доступно и клиенту, и Host-части, но разными cordis сервисами.

Если пользователь ещё не выбирал язык, клиент определяет временную локаль по `navigator.languages` с проверкой полного BCP 47 id и затем основного под-тега; последним проверяется `navigator.language`, после чего fallback — English: `packages/client/locale/src/client/index.ts:98-107, 496-527`. Host preference при наличии заменяет этот provisional locale.

## 2. Что доступно без интерфейсной locale-службы и чему доверяет dsh

`navigator.language` (а также упорядоченный `navigator.languages`) доступен в клиенте; dsh действительно использует их как браузерный выбор по умолчанию: `packages/client/locale/src/client/index.ts:504-527`. `LANG`/`LC_ALL` — нет такого: поиск по `packages/host`, `packages/client` не обнаружил использования этих env vars для языка UI. `Intl.DateTimeFormat().resolvedOptions().locale` — нет такого: dsh не использует его как выбор locale интерфейса (хотя другие Intl-вызовы, например для часовых поясов, существуют). `navigator.language` учитывается только как источник provisional client locale, а не Host locale. Если locale plugin/settings provider не подключены, самодостаточная LocaleRuntime имеет browser detection и English fallback; сохранённого выбора в таком составе нет (`packages/client/locale/src/client/index.ts:171-180, 182-192`).

## 3. Даты, время и относительное время в UI dsh

Общая функция относительного времени — `relativeTime(at, now)` в `packages/client/ui-primitives/src/relative-time.ts:18-35`: отрицательная разница обрезается до 0; до минуты — `now`; далее целые минуты, часы, дни; месяцы считаются блоками по 30 дней, годы — по 365 дней. Это bucket + число, а слова предоставляет словарь каждой поверхности.

Для списка сессий workspace форматирует локальные bucket-слова и суффикс «назад» через словарь: `packages/client/ui-workspace/src/client/rows/Rows.tsx:30-40`; русский эквивалент должен быть согласован с активной локалью и такими же границами/округлением. Словарь dsh для китайского использует `刚刚`, `{n}分钟/小时/天/月/年`, `{t}前`; английский — `now`, `{n}min/h/d/mo/y`, `{t} ago`: `packages/client/ui-workspace/src/client/locales.ts:64-71, 134-141`. В поисковых ссылках на сессии та же bucket-функция, но без обёртки «ago»: `packages/client/ui-reference/src/client/index.ts:203-224`.

Абсолютная дата создания workspace row формируется компонентами даты/времени и locale-шаблонами, а не `toLocaleString`, чтобы смена языка приложения не смешивалась с языком браузера: `packages/client/ui-workspace/src/client/rows/Rows.tsx:42-52`; шаблоны: `packages/client/ui-workspace/src/client/locales.ts:62-64, 132-134`. В timeline записанное время отдельно вызывается как `toLocaleTimeString(undefined, ...)`, то есть с locale окружения браузера: `packages/client/ui-trajectory/src/client/TrajectoryTimeline.tsx:97-104`. Универсального единого форматтера всех абсолютных дат в dsh нет; для совпадения с конкретным соседним UI нужно ориентироваться на его поверхность.

## 4. Горячая смена и событие

Да, без перезагрузки экрана. `LocaleRuntime.setLocale` публикует новое состояние сразу при изменении и пишет выбор в Host settings (`packages/client/locale/src/client/index.ts:224-242`). При смене публикуется новый snapshot, испускается `locale/change`, после чего уведомляются подписчики (`packages/client/locale/src/client/index.ts:471-492`); подписчики LocaleFace также поддерживаются через `getSnapshot/subscribe` (`packages/client/locale/src/client/index.ts:203-222`). При изменении активного locale обновляется `<html lang>` и синхронизируется store строки настроек (`packages/client/locale/src/client/index.ts:539-564`). Внешнее изменение settings может быть горячим: provider по умолчанию следит за документом (`packages/settings/settings-file/src/index.ts:21-30, 56-67`), а LocaleRuntime подписан на изменения settings scope (`packages/client/locale/src/client/index.ts:189-192`). Событие — `locale/change` с `LocaleSnapshot`; регистрация словаря отдельно это событие не эмитит (`packages/client/locale/src/client/index.ts:85-95`).

## Вывод для плана 2t

В клиенте следует подключаться к `ctx.locale` как к источнику активного языка, а не придумывать отдельную настройку или выбирать язык по `Intl`/env. Словари плагина должны реагировать на смену locale через стандартный locale seat/подписку; при собственном «N ч назад» нужно повторить dsh bucket-границы и локализовать структуру строки. При необходимости синхронизировать Host-логику, доступна настройка `ctx.settings` namespace `locale`, но Host не имеет `ctx.locale`.

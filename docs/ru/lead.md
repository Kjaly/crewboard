# Ведущий

[English](../en/lead.md) | **Русский**

Ведущий — это чат, с которым вы разговариваете, подключённый к Crewboard по MCP: Claude Code, Codex, dsh или любой другой MCP-клиент. Он превращает то, что вы хотите, в цель и поручения, отвечает исполнителям, поднимает к вам только то, что не может решить сам, и закрывает работу. Какой клиент ведёт, Crewboard узнаёт из самого MCP-подключения и показывает на экране; новый чат ведущего может подхватить цель через `crewboard_adopt_goal`.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `crewboard_start_goal` | Ставит цель, о которой договорились с владельцем. Возвращает `goalId`. |
| `crewboard_agents` | Возвращает `{ agents, presets }`: доступных агентов с возможностями и включённые пресеты. |
| `crewboard_assign` | Отдаёт часть работы исполнителю: название, критерии, вид результата (`local`, `branch`, `answer`, `decision`), `preset` или провайдер (имя агента из `crewboard_agents`), при желании модель и `effort` (из списка `efforts` агента; если он пуст, поле не передаётся), родителя и зависимости `after`, а в `quote` — реплику владельца, из которой поручение родилось. |
| `crewboard_inbox` | Возвращает всё, что исполнители и владелец прислали и что ведущий ещё не подтвердил. Следующий вызов подтверждает прошлую порцию. |
| `crewboard_answer` | Отвечает на вопрос исполнителя, тот продолжает работу. |
| `crewboard_escalate` | Передаёт вопрос исполнителя владельцу с объяснением в `why`. |
| `crewboard_steer` | Добавляет уточнение к идущей работе. |
| `crewboard_return` | Возвращает итог с замечанием. |
| `crewboard_close` | Закрывает работу, которая выполнила критерии. |
| `crewboard_cancel` | Отменяет поручение и всё, что под ним, и останавливает их запуски. |
| `crewboard_decide_request` | Решает по просьбе владельца с экрана: согласие выполняет её, отказ требует причины, которую владелец прочитает. |
| `crewboard_status` | Цель деревом: статус каждого поручения и чем оно занято сейчас. |
| `crewboard_adopt_goal` | Подхватывает цель, которую начал другой чат. |

В каждом вызове есть `project` — абсолютный путь к репозиторию, где работает ведущий. Crewboard берёт корень этого Git-репозитория.

## Как выбрать пресет

Перед назначением прочитайте `crewboard_agents`: пользователь может заменить или выключить любой [пресет](workers.md#пресеты). Встроенные варианты: `cheap` (DeepSeek) для рутины, `normal` (Codex `gpt-6.1-sol`, medium) для обычной разработки, `hard` (та же модель, high) для сложных рассуждений и `review` (Claude opus) для независимой проверки. Передайте `preset` вместо `provider` в `crewboard_assign`; явные `model`/`effort` имеют приоритет. Поле `note`, если задано, подсказывает ведущему, когда брать пресет.

## Как ведущий узнаёт новости

Ведущий держит в фоне такую команду:

```sh
crewboard wait --project /path/to/repo
```

Она завершается с кодом 0, как только во входящих ведущего что-то появилось, с кодом 2 по истечении `--timeout` (по умолчанию 10 минут) без новостей и с кодом 1, если сервер не запущен. После завершения ведущий читает `crewboard_inbox`, действует и снова запускает ожидание. События остаются во входящих, пока ведущий снова не вызовет `crewboard_inbox`, поэтому чат ведущего, оборвавшийся до действий, их не теряет: их получит следующий ведущий. Пока ведущий ждёт, экран считает его на связи.

## Вопросы

Исполнитель, который не может продолжать, заканчивает запуск вопросом. Ведущий отвечает через `crewboard_answer`, а если решить может только владелец, передаёт вопрос через `crewboard_escalate` и говорит вам об этом в чате. Ваш ответ с экрана доходит и до исполнителя, и до входящих ведущего.

## Итоги

Исполнитель заканчивает итогом. Узел показывается как «Ждёт ведущего»: ход за ним. Ведущий закрывает работу по критериям или возвращает её с замечанием. Возвращённая работа продолжается в той же рабочей копии, замечание попадает в контекст.

## Просьбы владельца

С экрана можно попросить что-то сделать с узлом: уточнить, остановить, передать другому провайдеру, начать раньше, переоткрыть или обсудить. Каждая просьба приходит ведущему во входящие как `owner_requested`. Ведущий решает через `crewboard_decide_request`. Согласие выполняет действие. Отказ требует причины, и экран показывает её на узле. Решение ведущего окончательное. Если вы не согласны, скажите ему в чате.

Передачу можно попросить и для работы в очереди. Согласие меняет агента/модель/effort, оставляя работу в очереди с прежними зависимостями; запуск не начинается. При передаче `effort: null` снимает override поручения, в том числе у того же агента: следующий запуск возьмёт умолчание агента или CLI. Если `effort` не передан, у того же агента сохраняется текущий выбор. Снимки прошлых запусков и настройки ожидающего запуска остаются раздельными.

Одно действие не ждёт ведущего: «Аварийная остановка» на любой идущей работе. Она сразу останавливает работу и всё, что под ней, а ведущий узнаёт о ней из входящих.

## Несколько чатов, одна цель

Цель живёт дольше чата, который её начал. Новый чат Claude Code может подхватить её через `crewboard_adopt_goal`, и тогда «История» покажет оба разговора по порядку. Цель, чей ведущий молчит больше суток, показывается «На паузе», пока её не подхватит ведущий.

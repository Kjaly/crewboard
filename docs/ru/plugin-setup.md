# Подключение плагина

[Документация](../README.md) · [English](../en/plugin-setup.md) | **Русский**

Плагин Crewboard (`dsh-crewboard`) добавляет в [DeepSeek Harness](https://www.npmjs.com/package/@deepseek-ai/dsh) (`dsh`) экран Crewboard, настройки, уведомления и инструменты `orchestra_*`. CLI он не нужен — ставьте плагин, когда захотите видеть работу на экране.

Шаги с пометкой **«проверьте в своём dsh»** зависят от версии dsh и профиля; проверить их на каждой установке я не мог.

## Что нужно

- Node.js 24 или новее. См. [README: установка](../../README.ru.md#установка).
- dsh с профилем `web` (`npm install -g @deepseek-ai/dsh`): браузерная часть плагина рассчитана на веб-клиент.
- Для чата-оркестратора: ключ DeepSeek API в dsh (**Settings → Models** или `DEEPSEEK_API_KEY`).
- Абсолютные пути к репозиториям, которые вы хотите видеть.

## Установка

Релиз в npm ещё не опубликован, поэтому ставьте плагин из каталога с исходниками. Сначала соберите его (см. [CONTRIBUTING.md](../../CONTRIBUTING.md) (на английском)), затем добавьте по пути:

```sh
dsh plugin --profile web add "$PWD/packages/plugin"
```

`dsh plugin` передаёт аргументы pnpm внутри каталога профиля, так что это подключает собранный плагин в этот профиль. После публикации релиза сопровождающим тот же шаг станет `dsh plugin --profile web add dsh-crewboard`.

Перезапустите профиль (`dsh web`) и откройте **Orchestration**: иконка графа (три связанные точки) в левой колонке dsh, подсказка при наведении — Orchestration. **Проверьте в своём dsh**, что пункт появился; если нет — см. [раздел о неполадках](troubleshooting.md#экран-не-появляется-в-dsh).

Чтобы обновить, выполните команду установки ещё раз (`dsh plugin --profile web add "$PWD/packages/plugin"` для каталога с исходниками или имя пакета после публикации) и перезапустите `dsh web`.

## Подключите репозитории

Плагин берёт репозитории из трёх источников, объединяя их без повторов:

1. **Список репозиториев Crewboard**, `~/.config/crewboard/repos.json`. Обычно достаточно его, и только в него пишет сам Crewboard:
   - на экране нажмите **+** рядом с **Репозитории** и вставьте абсолютный путь к папке (`~/src/app` тоже подходит). Папка должна быть Git-репозиторием или рабочей копией и ещё не быть в списке; она появляется сразу, а папка без плана открывается на приветственном экране;
   - в терминале `crewboard init` и `crewboard plan new` вносят репозиторий, в котором запущены, а `crewboard repo add [путь]` вносит его вручную (см. [CLI: репозитории на экране](cli.md#репозитории-на-экране)).
2. **Воркспейсы dsh**: репозитории, открытые в dsh, появляются сами.
3. **Настройка плагина `repos`** — список абсолютных путей в строке плагина `crewboard` конфигурации профиля dsh (**проверьте в своём dsh**, где профиль хранит настройки плагинов), — и переменная окружения `CREWBOARD_REPOS`: абсолютные пути через `:`, читается при запуске dsh:

   ```sh
   CREWBOARD_REPOS="$HOME/src/api:$HOME/src/web" dsh web
   ```

   Относительные пути пропускаются. Старое имя переменной, `ORCH_REPOS`, тоже читается.

Все три источника перечитываются при каждом обновлении, так что репозиторий, добавленный в любой из них, появляется без перезапуска dsh.

**Рабочие копии.** Для каждого репозитория из списков плагин показывает и планы в его рабочих копиях Git (`git worktree list`): копия, где есть `.orchestration/`, появляется под своим репозиторием с пометкой **рабочая копия**. Собственные копии задач Crewboard (`<репозиторий>-orch-<задача>`) отдельными планами не показываются никогда.

**Одна папка — одна строка.** Пути сравниваются после разрешения символических ссылок, поэтому `/tmp/app` и `/private/tmp/app` на macOS или путь с косой чертой в конце — одна и та же папка в любом списке. Строка сохраняет написание, под которым папка попала в список первой.

**Меню строки репозитория** («…» или правый клик) содержит **Новый план…** — введите цель и нажмите Enter — и **Убрать из списка**. Этот пункт забывает папку только в списке Crewboard: файлы, планы и рабочие копии не трогаются. Воркспейс dsh или путь из `repos` там не убрать: пункт неактивен и говорит, где это сделать. Папка из списка, которой больше нет, остаётся в дереве с пометкой **нет на диске**, пока её не уберут. Её запись в списке Crewboard сохраняется как есть — папка не пропадает из списка только потому, что экран пометил её отсутствующей; уберите её кнопкой **Убрать из списка** или добавьте новый путь, если папка переехала.

Другие настройки в той же строке:

| Настройка | По умолчанию | Что означает |
| --- | --- | --- |
| `repos` | `[]` | Абсолютные пути к репозиториям. |
| `refreshMs` | `30000` | Как часто обновлять данные, в миллисекундах; не меньше `5000`. Изменения файлов отслеживаются и так. |
| `notifications` | `true` | Уведомления, когда работа ждёт вас. |

Если плагин раньше был настроен под старым идентификатором `dsh-orchestra`, его список `repos` по-прежнему читается как запасной.

## Что плагину нужно от dsh

- Экран, уведомления, инструменты чата и фоновое наблюдение работают, только пока запущен хост dsh. CLI работает с теми же планами и без него.
- Чат, привязанный к плану, работает только с этим планом: хост добавляет план к каждому вызову `orchestra_*` и отклоняет вызов, в котором указан другой план или репозиторий. `orchestra_attention` возвращает тот же список, что `crewboard attention --json`, а `orchestra_task` — ту же структуру, что `crewboard task show <id> --json` ([CLI](cli.md#задачи-и-решения)).
- Архивный план на экране открывается только для чтения; текущий план CLI и агентов не меняется. Активный план при открытии, как и раньше, становится текущим.
- Сервисы dsh плагин получает через внедрение зависимостей. Если в вашей версии dsh нет какого-то необязательного сервиса, недоступна только связанная с ним функция, а экран продолжает работать.
- Принять, вернуть и заменить задачу на экране можно только после нативного подтверждения macOS. **Проверьте в своём dsh**, что окно появляется, прежде чем принимать решения на экране; интерактивное подтверждение в CLI доступно всегда.
- Экран следует переключателю языка dsh. Если русского нет в списке языков dsh, плагин его добавляет.

## Первый взгляд

Откройте **Orchestration**. Если в репозитории нет плана, приветственный экран предложит пример плана, черновик плана по спецификации и настройку воркеров. Если план есть — откроются [экраны «Граф», «Работа» и «Итоги»](getting-started.md#экран).

Настройки — в разделе **Crewboard** настроек dsh: воркеры и проверка доступа к ним, порядок по классам задач, пресеты, уведомления и очистка рабочих копий. CLI и экран читают одни и те же файлы в `~/.config/crewboard/`, поэтому изменение в одном месте сразу видно в другом.

На экране «Воркеры» три секции ([воркеры](workers.md#экран-воркеры-три-секции)), и каждый воркер ровно в одной:

- **Модели по API приходят из dsh.** Каждая модель, настроенная в **Settings → Models** в dsh, показывается как воркер «<Модель> · через dsh», сгруппированный по провайдеру, и список следует за конфигурацией dsh без перезапуска. Ключи остаются в dsh, Crewboard их не читает. Плагин получает каталог моделей через контроллер сессий dsh; если в вашем dsh его нет, настройки говорят, что модели dsh не показаны. Они в секции **Через dsh (API)**. Модель dsh, убранная из dsh, но всё ещё названная в каком-то списке, помечена **Заблокирован в dsh**, и её переключатель недоступен. Модель Anthropic/Claude, направленная через dsh, — исключение: политика API-only для Claude отказывает в запуске (см. [автоматизацию Claude](workers.md#автоматизация-claude-подписки-и-безопасность-аккаунта)).
- **Подписки подключаете вы.** Codex, Devin и другие CLI по подписке работают на аккаунте с выполненным входом: у каждого есть блок в секции **Подписки** с состоянием, командой входа и кнопкой **Проверить доступ**, затем **Добавить модели**, чтобы выбрать модели и усилия; Crewboard добавит по воркеру на каждую. Claude Code по-прежнему показан под этим устаревшим заголовком секции (секция следует за транспортом, а заголовок старше политики), но автоматические запуски Claude больше не используют подписочный вход: нужен явный `ANTHROPIC_API_KEY` и официальный endpoint Anthropic (см. [политику API-only](../notes/2026-09-28-anthropic-automation-policy.md)). Вход через Console OAuth и другие транспорты Anthropic этим адаптером не поддерживаются — это не запрет. Модель с несколькими усилиями — одна строка с чипом усилия на каждого воркера.
- **Другое / импортированное** свёрнуто: дубликаты по CLI, модели и усилию (**Оставить один**, **Убрать остальные**), профили из старого инструмента (**Добавить как воркер**, **Убрать**) и id, которые ничем не заданы.

Переключатель **Включён** говорит, может ли оркестратор брать воркера. **Где используется** — чипы всех списков, где он стоит: маршрутизации («маршрутизация · исследование №2») и каждого пресета («Claude · код №1»); чип открывает этот пресет.

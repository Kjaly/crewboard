# Исполнители

[English](../en/workers.md) | **Русский**

Исполнители — это агенты, которые выполняют поручения. Crewboard запускает каждого через его собственную командную строку, читает, что он делает, и передаёт ведущему его вопросы и итоги.

## Встроенные агенты

| Агент | Как запускается | Модель по умолчанию | Что нужно |
| --- | --- | --- | --- |
| Codex | CLI `codex` | `gpt-6.1-sol` | `codex login` |
| Claude | CLI `claude` | `sonnet` | ваш вход в Claude Code |
| DeepSeek | `dsh`, DeepSeek Harness | `deepseek-flash` | установленный `dsh` и ключ DeepSeek в его настройках |

Эти три работают без файла настроек. Ведущий может указать другую модель для конкретного поручения (`model` в `crewboard_assign`). [Ваши агенты](#ваши-агенты) добавляют других.

### Как Claude входит

Claude-исполнитель — это официальный Claude Code, запущенный от вашего имени: с вашим входом (подписка Claude или ключ API — то, что Claude Code использует, когда вы запускаете его сами) и вашими настройками, `CLAUDE.md`, навыками и MCP-серверами. Crewboard никогда не читает, не хранит и не передаёт ваши учётные данные Claude.

По состоянию на 2026-11-02 `claude -p` при входе по плану Claude списывается с лимитов плана ([поддержка Anthropic](https://support.claude.com/en/articles/15036540)), а эти лимиты рассчитаны на обычное индивидуальное использование ([Claude Code: legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). Много параллельных Claude-исполнителей весь день может выйти за эти рамки, а изменение, которое выделит такое использование в отдельную оплату, Anthropic приостановила, но не отменила.

`CREWBOARD_CLAUDE_AUTH=isolated` возвращает изолированный режим: `claude --bare` с явным `ANTHROPIC_API_KEY` к официальному эндпоинту Anthropic, без ваших настроек, и отказ с причиной, если ключа нет или задан другой способ входа.

### Другая команда

`CREWBOARD_CLAUDE_COMMAND`, `CREWBOARD_CODEX_COMMAND` и `CREWBOARD_DSH_COMMAND` указывают Crewboard другой исполняемый файл: обёртку или закреплённую версию.

## Ваши агенты

Любой агент, которого умеют запускать адаптеры Crewboard, подключается записью в `~/.crewboard/agents.json` (или `$CREWBOARD_HOME/agents.json`). Пересобирать и перезапускать ничего не нужно: файл читается при каждом обращении.

```json
{
  "agents": {
    "kimi": { "label": "Kimi", "run": "dsh", "model": "moonshot/kimi-k3", "color": "#8b5cf6" },
    "glm": { "label": "GLM", "run": "opencode", "model": "zai/glm-5.2" },
    "codex": { "model": "gpt-6.1-terra" },
    "deepseek": { "enabled": false }
  }
}
```

| Поле | Что значит |
| --- | --- |
| `run` | адаптер: `claude`, `codex`, `dsh`, `opencode`, `cursor`, `gemini`, `grok` или `devin` |
| `model` | модель по умолчанию; для `dsh` вид `<маршрут>/<модель>` выбирает маршрут вашего профиля dsh |
| `label`, `color` | как агент выглядит на экране |
| `enabled` | `false` выключает агента, в том числе встроенного |

Запись с именем встроенного агента меняет только те поля, которые в ней указаны. Ведущий видит список через `crewboard_agents` и поручает работу по `id`; исполнитель может разбить работу на любых из них. Цель, где работал агент, которого вы потом убрали, по-прежнему открывается; новая работа для него отклоняется с причиной.

Если файл сломан, при запуске работы об этом сообщается с путём к файлу, и ведущий узнаёт причину.

### Модели по API через dsh

Модели по API (Kimi, GLM, Qwen и другим) нужна обвязка с инструментами; Crewboard использует для этого dsh. Crewboard запускает dsh с профилем `acp`, поэтому маршрут описывается там: настройки `@deepseek-ai/dsh-llm-pi-ai` в профиле принимают словарь `providers` с адресом, протоколом API, переменной окружения с ключом и моделями. Все поля описаны в README этого пакета в вашем профиле dsh. Например, маршрут `moonshot`:

```yaml
- name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      moonshot:
        apiKeyEnv: MOONSHOT_API_KEY
        api: openai-completions
        baseURL: https://api.moonshot.ai/v1
        models:
          - id: kimi-k3
```

Адрес и имя модели возьмите из документации провайдера. После этого запись `"model": "moonshot/kimi-k3"` в `agents.json` ведёт к ней. Ключ остаётся в вашем окружении: ни настройки dsh, ни Crewboard его не хранят.

## Виды результата

| Вид | Что сказано исполнителю |
| --- | --- |
| `local` | менять файлы в репозитории и не коммитить, изменения посмотрите вы |
| `branch` | работать в своей рабочей копии Git в `.crewboard/worktrees/` и коммитить там |
| `answer` | ничего не менять и ответить в итоге |
| `decision` | ничего не менять и дать решение с обоснованием |

## Как исполнитель сдаёт работу

Исполнитель заканчивает последнее сообщение одним из трёх блоков:

```text
<crewboard-report>что сделано и как это проверить</crewboard-report>

<crewboard-question>вопрос

- вариант один
- вариант два</crewboard-question>

<crewboard-split>
- [codex] Часть работы | критерий; критерий
- Другая часть (пойдёт на провайдере самого исполнителя)
</crewboard-split>
```

Если исполнитель забыл формат, он не зависает: всё его последнее сообщение считается итогом.

## Разбиение работы

Блоком `<crewboard-split>` исполнитель превращает свою задачу в поручения внутри себя, до 8 штук. Итог части уходит исполнителю, а не ведущему, и часть показывает «Доложено», пока ведущий не закроет родителя: это закрытие покрывает все части под ним. Crewboard отменяет часть, чей запуск упал (с причиной), и возобновляет исполнителя, когда все части доложат или закончатся, с их итогами в контексте. Части работы вида `branch` идут в рабочей копии самого исполнителя. Вопросы частей уходят ведущему, потому что исполнитель, пока ждёт, не запущен.

## Если запуск не стартует

Нет CLI, нет ключа или модель не разрешена — запуск сразу считается упавшим. Crewboard записывает это, показывает на узле «Запуск упал: …» с причиной, сообщает ведущему и сам не повторяет. Ведущий может уточнить задачу (это перезапускает её) или отменить.

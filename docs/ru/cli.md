# Справочник CLI

[Документация](../README.md) · [English](../en/cli.md) | **Русский**

`crewboard` и `orch` — одна и та же программа; при установке CLI появляются оба имени. Справка и сообщения используют то имя, которым вы её вызвали. Страница сверена с `crewboard --help` и исходным кодом команд версии 0.4.0.

Команды запускаются внутри Git-репозитория; план ищется от его корня. Вне репозитория команда остановится с сообщением «Не git-репозиторий».

## Общие флаги

| Флаг | Что означает |
| --- | --- |
| `--help`, `-h`, `help` | Показать сводку команд. Она же печатается после неизвестной команды. |
| `--lang en\|ru` | Язык интерфейса для этого вызова. Без флага русский выбирается, если `LC_ALL` или `LANG` начинается с `ru`, иначе английский. Часть сообщений движка плана пока только на русском. |
| `--plan <id>` | Работать не с текущим планом, а с указанным. Понимают `status`, `wait`, `task`, `accept`, `reject`, `supersede`, `drop`, `verify`, `start`, `run`, `events`, `trace`, `steer`, `stop`, `attention`, `cost` и `worktree`. Если текущий план в архиве, команда, которая меняет план, без `--plan` отклоняется. |

Коды выхода: `0` — успех, `1` — ошибка или отказ, `2` — ошибка в вызове. У `wait` код `2` означает, что истекло время ожидания.

Флага `--version` нет; версию покажет `npm ls -g crewboard`.

## Планы

| Команда | Что делает |
| --- | --- |
| `crewboard init [--goal "…"]` | Создаёт план `main` в `.orchestration/plan.json`, добавляет `.orchestration/` в `.git/info/exclude` и вносит корень репозитория (или рабочей копии) в [список репозиториев Crewboard](#репозитории-на-экране), чтобы экран показал план. Отказывает, если план уже есть. |
| `crewboard plan list` | Список планов: `●` текущий, `○` активный, `·` в архиве, с числом задач. |
| `crewboard plan new <id> --goal "…"` | Создаёт план и делает его текущим. Вносит место в список репозиториев Crewboard, как `init`. |
| `crewboard plan use <id>` | Делает план текущим. Архивный план можно сделать текущим, чтобы читать его; чтобы менять его, нужен `--plan <id>`. |
| `crewboard plan rename <id> --goal "…"` | Меняет цель плана. |
| `crewboard plan archive <id>` / `unarchive <id>` | Убирает завершённый план из списка активных или возвращает его. |
| `crewboard plan split <id> --from <план> --goal "…" --tasks a,b` | Переносит перечисленные задачи из `<план>` в новый план `<id>`. |
| `crewboard plan preset <id>` / `plan preset --clear` | Выбирает пресет воркеров для текущего плана или возвращает выбор репозитория. См. [воркеры](workers.md). |
| `crewboard chat unbind <план>` | Отвязывает план от чата dsh. |
| `crewboard status [--json] [--plan id]` | Задачи и их состояния, что их блокирует, что можно запускать, критический путь и действующий пресет. Принятая задача, чья ветка ещё не слита, помечена «принята, не слита», задача, которая её ждёт, — «ждёт слияния X»; отдельная строка перечисляет всё принятое, но не слитое. `--json` добавляет `unmerged` (id) и у задач — `unmerged` и `waitingMerge`. |

Значки в `status`: `·` отложена, `○` готова, `●` выполняется, `◐` на приёмке, `✓` принята, `✗` закрыта, `⏸` заблокирована, `⊘` заменена или закрыта как ненужная.

### Черновики планов

Воркер может составить черновик плана по спецификации; вы его проверяете и утверждаете как новый план.

| Команда | Что делает |
| --- | --- |
| `crewboard plan draft --from <файл> [-a <воркер>] [--wait]` | Запускает задание черновика. Без `-a` берётся первый воркер класса `research`. `--wait` дожидается конца. |
| `crewboard plan draft jobs` | Список заданий и их состояния. |
| `crewboard plan draft job <задание> [--wait]` | Показывает одно задание или следит за ним. |
| `crewboard plan draft repair <задание> [-a <воркер>] [--wait]` | Просит воркера исправить ответ, не совпавший с форматом черновика. |
| `crewboard plan draft drop <задание>` | Отбрасывает задание; промпты и ответы остаются в `.orchestration/draft-runs/`. |
| `crewboard plan draft recover` | Подхватывает задания, процесс которых прервался. |
| `crewboard plan drafts` | Список сохранённых черновиков. |
| `crewboard plan draft show <id>` | Показывает черновик и замечания к нему. |
| `crewboard plan approve <id>` | Только человек: превращает черновик в план, новый план становится текущим. Цикл зависимостей или отсутствующая зависимость не дают утвердить. |
| `crewboard plan discard <id>` | Удаляет черновик. |

## Задачи и решения

```text
crewboard task add <id> --title "…" [--kind implement|review|research|decision|root] [--lane "…"]
                   [--deps a,b] [--worker <профиль>] [--contract <файл>] [--class code|design|review|research] [--backlog]
crewboard task set <id> [--title "…"] [--lane "…"] [--deps a,b] [--worker <профиль>] [--contract <файл>]
                   [--class …] [--status backlog|ready] [--kind implement|review|research|decision|root]
```

| Флаг | Что означает |
| --- | --- |
| `--kind` | `implement` (по умолчанию), `review`, `research`, `decision` или `root`. Задачу `decision` закрывает только человек, запускать её нельзя. Задача `root` — собственная работа оркестратора: интеграция на стенде, запуск процессов, база владельца; воркер для неё не запускается никогда (см. [ниже](#собственная-работа-оркестратора)). `task set --kind` меняет тип открытой задачи; у принятой или вытесненной тип не меняется. |
| `--class` | Какой порядок воркеров применять: `code`, `design`, `review`, `research`. Без флага виды `review` и `research` получают одноимённый класс, остальные — `code`. |
| `--deps a,b` | Задачи, которые должны быть приняты раньше. `task set --deps ""` очищает список. |
| `--worker` | Собственный воркер задачи; используется вместо порядка класса. См. [воркеры](workers.md#как-выбирается-воркер). |
| `--contract` | Путь к контракту от корня репозитория. Без него запуск невозможен. |
| `--lane` | Произвольная метка группы для экрана. |
| `--backlog` / `--status` | Отложить задачу или сделать её готовой. `--status` принимает только `backlog` и `ready`. |

Решения — **только человек**: команда спрашивает `[y/N]` в интерактивном терминале и отказывает без него.

| Команда | Что делает |
| --- | --- |
| `crewboard accept <id>` | Принимает результат. Если вердикт отрицательный или спорный или в копии есть файлы без коммита (в ветке их нет), вопрос об этом скажет. После приёмки рабочая копия удаляется, если так настроена очистка. Пока ветка не слита, команда печатает точные команды, чтобы закоммитить оставшееся и слить; зависящие задачи ждут слияния ([приёмка](review.md#после-приёмки-слияние)). |
| `crewboard reject <id> --reason "…"` | Возвращает задачу с причиной; её можно запустить снова. |
| `crewboard supersede <id> --by <id>` | Закрывает задачу, потому что победил другой вариант. |
| `crewboard drop <id> --reason "…"` | Закрывает задачу, которая больше не нужна. Только человек и с подтверждением, как `accept` и `reject`. Статус задачи — **dropped** («закрыта как ненужная»): причина остаётся в истории, задача больше не становится готовой, уходит с критического пути и не запускается. `task set --status` её не открывает. Выполняющуюся задачу сначала остановите; принятую, заменённую или уже закрытую команда не трогает. На экране — пункт **Закрыть как ненужную…** в меню задачи. |

Проверка оркестратором — **агентам разрешено**. Она стоит между законченным запуском и вашим решением; см. [проверку оркестратором](review.md#проверка-оркестратором).

| Команда | Что делает |
| --- | --- |
| `crewboard verify <id>` | Берёт законченную задачу на проверку. На уже проверенной задаче ничего не меняет и печатает сводку: задача остаётся у человека. |
| `crewboard verify <id> --reopen` | Забирает проверенную задачу у человека, чтобы проверить её заново. |
| `crewboard verify <id> --done --note "…" [--confirm]` | Проверено: теперь задача ждёт человека, сводка показана над кнопкой **«Принять»**. Сводка обязательна. Сначала печатает вердикт, который увидит человек, и число изменённых файлов; если вердикт спорный или файлы не изменены, просит подтверждения — `y` в терминале, иначе `--confirm`. |
| `crewboard verify <id> --return "замечания" [--skip-preflight]` | Возвращает работу воркеру с замечаниями: новый запуск в той же рабочей копии. |
| `crewboard verify --setting on\|off\|default [--scope plan\|repo]` | Включает или выключает проверку для плана (по умолчанию) или репозитория либо сбрасывает сохранённое значение. По умолчанию проверка включена, пока у плана есть чат. `off` просит подтверждения человека. |

Все формы `verify` принимают `--plan <id>`. Проверить можно только законченную работу, которая ждёт приёмки.

Пакетной приёмки в CLI нет: `accept` принимает одну задачу, и его вопрос называет задачу, которую оркестратор не проверил. Принять несколько задач разом можно на экране («Принять пакетом») — он заранее отмечает только чистую работу и перед вопросом перечисляет решения и root-задачи без проверки оркестратора. На решении `accept` предлагает закрыть его: у решения нет вердикта. Отрицательный или спорный вердикт назван словами, а не кодом.

### Собственная работа оркестратора

Задача `root` — работа, которую оркестратор делает сам, а человек потом принимает. `crewboard run` от неё отказывается и называет эти команды — **агентам разрешено**:

| Команда | Что делает |
| --- | --- |
| `crewboard start <id>` | Берёт готовую root-задачу в работу: на графе, во вкладке «Работа» и в панели задачи она видна как «в работе у оркестратора». Пока она в работе, в «Ждут вас» её нет. |
| `crewboard verify <id> --done --note "…" [--report <файл>]` | Сделано: задача уходит на приёмку с пометкой «проверено оркестратором». `--report` — markdown-файл, который хранится с задачей и показывается там же, где отчёт воркера: первая строка `Результат: получен`, `отрицательный` или `заблокирован`, затем выполненные проверки, доказательства (коммиты, логи, команды) и как воспроизвести. Без `--report` отчётом служит сводка. |

Возвращённая root-задача снова готова к работе, причина — в её заметках; её начинают заново.

Решения готовятся так же: `crewboard verify <id> --done --note "…" [--report <файл>]` на решении записывает варианты и рекомендацию. Когда проверка оркестратором включена (по умолчанию — пока у плана есть чат), решение попадает в «Ждут вас», только когда его зависимости приняты **и** оно подготовлено; до этого экран пишет, что его готовит оркестратор. Когда проверка выключена — план ведут руками из CLI, без чата, — решение ждёт человека сразу после приёмки зависимостей, как раньше.

## Запуски

| Команда | Что делает |
| --- | --- |
| `crewboard run <id> [-a <профиль>] [--scope s] [--contract f] [--skip-preflight]` | Запускает воркера в рабочей копии задачи. `-a` выбирает воркера и записывает его в задачу. `--contract` заменяет контракт задачи на этот запуск. `--scope` подставляется вместо `{scope}` в базовую проверку рецепта (см. [рецепт рабочей копии](#рецепт-рабочей-копии)). `--skip-preflight` пропускает проверку доступности. Для dsh: `-a dsh` или `-a dsh/<модель>`, например `dsh/deepseek-flash`. Задачу, чья зависимость принята, но не слита, команда не запускает и называет команды слияния; `--allow-unmerged` запускает всё равно — только человек в интерактивном терминале, и в копии этой работы не будет. |
| `crewboard events <id>` | Лента событий последнего запуска задачи, включая ваши поправки. |
| `crewboard trace <id> [--json]` | Ходы, время модели, вызовы инструментов и поправки последнего запуска. |
| `crewboard steer <id> (--message "…" \| --file f) [--mode auto\|queue\|interrupt] [--relaunch] [--skip-preflight]` | Отправляет поправку работающему воркеру. `queue` ждёт конца текущего хода и становится следующим ходом; `auto` и `interrupt` доходят до воркера во время хода (Claude Code берёт поправку на следующем шаге, Codex перезапускает ход с ней). Каждая поправка заканчивается как подтверждённая или недоставленная с причиной. Если запуск уже закончился, `--relaunch` начинает новый запуск с этой поправкой. |
| `crewboard continue <id>` | Продолжает запуск, закончившийся недоделанным — без отчёта и с незакоммиченной работой (см. [Недоделанные запуски](review.md#недоделанные-запуски)): новый запуск в той же рабочей копии с указанием доделать работу, закоммитить её и отчитаться. Отказ, если последний запуск не закончился недоделанным. |
| `crewboard stop <id>` | Останавливает последний запуск. Запуск Claude Code или Codex, чей последний ход уже успешно закончился (воркер выдал финальный отчёт), завершается как выполненный и уходит на ревью; запуск, остановленный посреди хода, отменяется. |
| `crewboard attention [--all] [--json] [--alarms]` | Что ждёт человека — тот же список, что «Ждут вас» на экране: задачи на проверке (и проверил ли их оркестратор), решения, упавшие или зависшие запуски и другие планы, которые ждут. Текст сгруппирован по видам; принятое, но не слитое (`unmerged`, команда слияния — в `hint`); в `--json` у каждого пункта есть `kind` (`review`, `decision`, `unmerged`, `attention`, `plan`), а также `root`, `planId`, `taskId` и для тревог — `runId`. Строки плана-примера появляются, только когда спрошен сам пример (открытый план репозитория или `--plan` с его id); они идут последними, помечены `example` и не считаются. `--all` их не показывает. `--all` — по всем репозиториям, которые показывает экран (работает из любой папки). `--alarms` — только тревоги запусков (упал, завис, повторяется), как команда работала раньше. «Всё спокойно.» — только когда ничего не ждёт. |
| `crewboard cost [--json]` | Итоги по воркерам: запуски, минуты, списанные деньги (`деньги $X`) и оценка по API-ценам (`оценка ≈$Y`) рядом, без общей суммы, токены, квота. Для плана без запусков — `В плане <id> запусков нет.` См. [затраты](costs.md). |
| `crewboard wait [--for decision\|finished\|check\|any] [--tasks a,b] [--interval 15s] [--timeout 30m] [--json]` | Ждёт, пока задачу решат, запуск закончится или случится шаг проверки оркестратором (`check`). Ждёт следующего изменения; с `--tasks`, если все перечисленные задачи уже там (запуск закончен, проверка сделана, решение принято или задача закрыта), сразу выходит с `0` и печатает их с пометкой `уже` (в JSON — `"already": true`). Выход `0` — событие, `2` — время вышло (30 минут, если `--timeout` не задан), `1` — ошибка. Длительности: `ms`, `s`, `m`, `h`; число без единиц — секунды. Предназначена для фонового запуска оркестрирующим агентом; заодно обновляет состояние воркеров, когда экран dsh закрыт. |

Запуск отклоняется, если задача заблокирована, уже выполняется, принята или заменена, является решением или root-задачей, не имеет контракта или ни один воркер не прошёл проверку. Сообщение называет причину, а отказ длиннее одной строки (красный базовый прогон с выводом тестов, список проверок) заканчивается строкой `✗ <id> не запущена: <причина>`, так что последняя строка вывода — всегда причина.

## Воркеры и пресеты

| Команда | Что делает |
| --- | --- |
| `crewboard workers` | Реестр и порядок воркеров для каждого класса, с отключёнными воркерами и причинами. |
| `crewboard workers add <id> --kind dsh\|claude\|codex\|devin --label "…" [--model m] [--transport t] [--effort e] [--billing API\|подписка\|промо]` | Регистрирует или обновляет воркера. По умолчанию `--billing` — подписка для Claude и Codex, промо для Devin и API для dsh. |
| `crewboard workers rm <id>` | Удаляет воркера, его псевдонимы и ссылки на него в порядке классов. |
| `crewboard workers disable <id> [--reason "…"]` / `enable <id>` | Отключает воркера на этой машине или включает обратно. Отключённый воркер не запускается никогда. |
| `crewboard workers route <класс> <id,id,…>` | Задаёт общий для машины порядок одного класса. |
| `crewboard presets [list]` | Действующий пресет и его источник, затем сохранённые пресеты. |
| `crewboard presets add\|set <id> --label "…" --code a,b --design a,b --review a,b --research a,b` | Сохраняет именованный порядок классов. Нужны все четыре флага классов; пустое значение оставляет класс пустым. |
| `crewboard presets rm <id>` | Удаляет пресет; репозитории и планы, где он был выбран, возвращаются к **«Все воркеры»**. |
| `crewboard repo preset <id>` | Выбирает пресет для репозитория. Встроенный — `all-workers`. |
| `crewboard plan preset <id\|--clear>` | Выбирает пресет для текущего плана. |

## Репозитории на экране

Экран показывает репозитории из трёх списков, объединяя их без повторов: воркспейсы dsh, настройка плагина `repos` (вместе с `CREWBOARD_REPOS`) и собственный список Crewboard в `~/.config/crewboard/repos.json`. CLI пишет только в последний. `crewboard init` и `crewboard plan new` вносят место, где работают; вручную список ведут эти команды:

| Команда | Что делает |
| --- | --- |
| `crewboard repo add [путь]` | Вносит этот репозиторий или репозиторий по `пути` в список Crewboard. `~` раскрывается; вложенная папка вносится как корень своего репозитория, рабочая копия — как свой корень. Отказывает, если папка не Git-репозиторий и не рабочая копия. |
| `crewboard repo list` | Все места, которые показывает экран, и откуда они: `воркспейс dsh`, `настройка repos плагина`, `список Crewboard` или `рабочая копия <репозиторий>`. Папка, которой больше нет, помечена `нет на диске`. |
| `crewboard repo rm <путь>` | Убирает путь из списка Crewboard. Файлы, планы и рабочие копии остаются на диске. Путь, которого больше нет, убирается так же. Воркспейс dsh или путь из `repos` здесь не убрать; сообщение говорит, где это сделать. |

Рабочие копии находятся сами: для каждого репозитория из списков экран выполняет `git worktree list` и показывает каждую копию, где есть план (`.orchestration/`), — под репозиторием, с пометкой **рабочая копия**. Собственные копии задач Crewboard (`<репозиторий>-orch-<задача>`, рядом с репозиторием) никогда не показываются отдельными планами, даже если в них появился файл плана: это рабочее место воркера над задачей, а не отдельное место.

Если команда работает с планом, которого экран не показывает, после своего вывода она печатает одно предупреждение с командой, которая это исправит (`crewboard repo add`). Предупреждение появляется, только если установлен dsh (есть `~/.dsh`), и никогда — в копии задачи.

## Окружение

| Команда | Что делает |
| --- | --- |
| `crewboard preflight [-a <профиль>] [--probe] [--json]` | Проверяет, что CLI воркеров установлены и вход выполнен. Без `-a` проверяются все включённые профили. С `-a` проверяется ещё и минимальная версия Claude Code для модели. `--probe` отправляет пробный запрос, где это поддерживается. Выход `1`, если проверка не прошла. |
| `crewboard worktree prepare <id> [--scope s]` | Создаёт или переиспользует рабочую копию задачи и выполняет рецепт, не запуская воркера. |
| `crewboard worktree list` | Рабочие копии задач: чистые или изменённые, приняты или нет, и последний базовый прогон. |
| `crewboard worktree gc` | Предпросмотр: какие копии можно удалить, какие остаются и почему, с размерами. Ничего не удаляет. |
| `crewboard worktree gc --yes` | Удаляет подходящие копии. Непринятые, запущенные, изменённые, неслитые и три последние принятые остаются. Удаление — через `git worktree remove` без force. Печатает каждую убранную копию или `Ничего не убрано: оставлено N — …` с причинами. |
| `crewboard worktree gc --force <id>` | Только человек: удаляет одну копию, даже если в ней есть изменения. |

### Рецепт рабочей копии

Новая рабочая копия — это чистый checkout `HEAD`. Необязательный `.orchestration/recipes.json` готовит её до запуска воркера:

```json
{
  "setup": ["pnpm install --frozen-lockfile", { "copy": ".env.local" }],
  "env": { "unset": ["NODE_OPTIONS"] },
  "baseline": "pnpm test {scope}",
  "timeoutSec": 300
}
```

Шаги `setup` — это команды оболочки или `{ "copy": "<путь>" }`, чтобы скопировать файл или папку из основного checkout, например неотслеживаемый `.env.local`. `env.unset` убирает переменные из окружения шагов. `baseline` — проверка, которая должна пройти, прежде чем задача уйдёт воркеру: красная базовая проверка отменяет запуск. У каждого шага свой лимит `timeoutSec` (по умолчанию 300). Уже существующая копия перематывается (fast-forward) на `HEAD` репозитория, если в ней нет незакоммиченных изменений. Её `setup` выполняется повторно, только если он так и не завершился. `baseline` прогоняется снова, если последний прогон не был зелёным, шёл с другой командой или копия тогда ещё не содержала текущий `HEAD` репозитория. Собственные коммиты воркера изменением не считаются. Поэтому красный или неизвестный базовый прогон, например в копии, созданной старой версией, всегда повторяется до старта воркера. Последний результат (коммит, команда, зелёный или красный, время) показывают `crewboard worktree list` и панель задачи.

## Файлы и переменные окружения

| Путь | Содержимое |
| --- | --- |
| `.orchestration/plan.json`, `.orchestration/plans/*.json` | Планы; `.orchestration/current` называет текущий. |
| `.orchestration/runs/<запуск>/evidence.json` | Доказательства, сохранённые по завершении запуска. |
| `.orchestration/preset.json` | Пресет, выбранный для репозитория. |
| `.orchestration/recipes.json` | Необязательный [рецепт рабочей копии](#рецепт-рабочей-копии). |
| `~/.config/crewboard/profiles.json` | Профили воркеров, псевдонимы, общий порядок классов, отключённые воркеры. |
| `~/.config/crewboard/workers.json` | Реестр воркеров. |
| `~/.config/crewboard/presets.json` | Сохранённые пресеты. |
| `~/.config/crewboard/repos.json` | Список репозиториев Crewboard: места, которые экран показывает помимо воркспейсов dsh и `repos` плагина. |

`CREWBOARD_PROFILES_FILE`, `CREWBOARD_WORKERS_FILE`, `CREWBOARD_PRESETS_FILE` и `CREWBOARD_REPOS_FILE` задают другое расположение этих файлов; старые имена `ORCH_*` тоже читаются. При первом запуске существующий `~/.config/dsh-orchestra/` копируется в `~/.config/crewboard/`; оригинал не меняется.

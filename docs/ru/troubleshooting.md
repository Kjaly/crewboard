# Если что-то не так

[English](../en/troubleshooting.md) | **Русский**

## Экран пишет «Нет связи с сервером»

Сервер остановился. Запустите его снова командой `crewboard serve`: экран сам переподключится и перечитает данные.

## Порт занят

`crewboard serve` пишет `port 4700 is in use` и завершается. Возможно, Crewboard уже запущен: откройте http://127.0.0.1:4700/. Иначе запустите на другом порту — `crewboard serve --port 4710`. Подключите ведущего к тому же порту — `claude mcp add --scope user --transport http crewboard http://127.0.0.1:4710/mcp`, — а ожидание ведущего запускайте с `--port 4710`.

## Исполнитель не готов

`crewboard doctor` показывает для каждого исполнителя первую непройденную проверку и что делать: поставить CLI, обновить его, войти. Пустой экран показывает тот же список.

## Ведущий не видит инструменты

Проверьте, что сервер запущен и что клиент ведущего показывает `crewboard`: `claude mcp list` в Claude Code, `codex mcp list` в Codex, запись профиля в dsh. После перезапуска сервера ведущий переподключается при следующем вызове. Если не переподключился, начните чат заново. В Claude Code сервер, добавленный без `--scope user`, есть только в той папке, где его добавили: добавьте его заново через `crewboard connect claude` (он использует пользовательскую область).

## Поручение Claude пишет «Запуск упал: … anthropic_api_key_missing»

Так бывает только с `CREWBOARD_CLAUDE_AUTH=isolated`: этому режиму нужен `ANTHROPIC_API_KEY` в окружении сервера. Без переменной Claude работает по вашему входу в Claude Code. Подробнее в руководстве по [исполнителям](workers.md#как-claude-входит).

## Поручение Codex падает с «model not supported»

Аккаунту недоступна эта модель. Попросите ведущего указать другую `model` или проверьте, что `codex` работает сам по себе.

## «История» показывает ход работы, а не разговор

Crewboard читает транскрипты ведущего из `~/.claude/projects` (Claude Code), `~/.codex/sessions` (Codex) и `~/.dsh/sessions` (dsh) — чаты, которые работали в репозитории или его подпапках и вызывали Crewboard для этой цели. Он их не находит, если ведущий — другой клиент, работал в папке вне репозитория или транскрипты удалены; тогда вкладка показывает ход работы из журнала Crewboard. Переменные `CREWBOARD_CLAUDE_PROJECTS`, `CREWBOARD_CODEX_SESSIONS` и `CREWBOARD_DSH_SESSIONS` указывают другие папки.

## Ведущий показан «не на связи», хотя работает

Ведущий считается на связи, пока он вызывает Crewboard или ждёт через `crewboard wait`. Если ведущий долго думает без того и другого, через 10 минут появляется «ведущий не на связи». Следующий вызов это исправляет.

## Цель «На паузе»

Её ведущий молчит больше суток. Откройте чат в репозитории и попросите подхватить цель — он вызовет `crewboard_adopt_goal`.

## `crewboard wait` завершается с кодом 1

На этом порту не запущен сервер или путь не внутри Git-репозитория. Сообщение скажет, что именно.

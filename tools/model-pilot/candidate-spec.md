# Candidate specification (v1)

Write pure synchronous JavaScript exporting `assessClosure(state)`. No mutation, I/O, network, or dependency release. Return exactly `{ action, reason, releasesDependents }`.

State fields: `status` is `in_review|accepted|closed|merged|other`; `kind` is `task|root|decision`; `headFresh`, `contractFresh`, `dirty`, `conflicts`, `currentOrchestratorPositive`, `humanReview`, `decisionGate`, `positiveMerge` are booleans; `check` is `pending|failed|required_failed|green|not_required`; `worker` is `completed|blocked|other`; `verdict` is `positive|negative|uncertain`; `dependencies` is an array of `{status: closed|open, polarity: positive|negative}`. `check: green|not_required` means independent orchestrator review is done and required receipts are current, never merely a worker claim. `currentOrchestratorPositive` means explicit current independent orchestrator positive attestation, not task kind. `positiveMerge` means confirmed positive merge.

Compute `effectivePositive = currentOrchestratorPositive || (worker === 'completed' && verdict === 'positive')`; compute `allDepsPositive` iff every dependency is closed and positive. Apply first-match precedence exactly: (1) malformed schema → `refresh_state/invalid_state/false`; (2) `closed|merged` → `already_closed/already_closed`, releases only if `positiveMerge && effectivePositive && kind==='task' && allDepsPositive`; (3) stale HEAD → `refresh_head/stale_head/false`; (4) stale contract → `refresh_contract/stale_contract/false`; (5) dirty or conflicts → `resolve_dirty_or_conflicts/dirty_or_conflicts/false`; (6) pending check → `wait_for_check/check_pending/false`; (7) failed|required_failed check → `rerun_required_gate/required_gate_failed/false`; (8) humanReview → `request_human_review/human_review/false`; (9) root kind → `request_human_review/root_requires_human/false`; (10) decision kind or decisionGate → `confirm_decision/decision_gate/false`; (11) status neither in_review nor accepted → `continue_work/not_in_review/false`; (12) dependencies not all positive → `continue_work/prerequisite/false`; (13) not effectivePositive → `continue_work/blocked_result/false`; (14) accepted → `merge/accepted_unmerged/false`; (15) in_review → `close/ready/false`.

Thus READY03 (historical blocked worker, negative worker verdict, current orchestrator positive attestation, current fresh/green state, ordinary task) returns `close/ready/false`; without attestation it returns `continue_work/blocked_result/false`. Attestation never overrides stale identity, dirty/conflict, failed/pending gates, human review, root/decision rules, or prerequisites. Root stays human-controlled despite positive attestation. Closed negative never reopens. Accepted but unmerged never releases. Only confirmed positive merged ordinary task may predict release, and only with all-positive dependencies. This public smoke suite is not blind and not evidence of model superiority.
